# 抖音功能分支验证记录

- 基线：v1.7.0.6；分支：codex/douyin-spark；体验版本：1.8.0.4。
- 截图视觉检查：15 项，通过。覆盖消息栏、完整名称点查、搜索框、表情按钮、续火花标签、200% 缩放、空白图像拒绝、取消、视觉节点返回，以及定向聊天标题回调的完整名称核对与不匹配拒绝；没有发送消息。
- 流程检查：67 项，通过。包括自动启动顺序、无安装时停止、启动中取消、未确认发送不重试、读取进程超时及取消后可重新请求、错误焦点不输入、延迟焦点有界重试、输入回读失败不放行、视觉与原生控件切换时的目标复核、同名多重性稳定判断、杂项 OCR 变化不阻塞完全同名结果、搜索结果的“发消息”按钮定位、浮动通知及嵌套发送箭头不误认成表情，以及精简诊断不包含联系人名称或聊天正文。
- 无 Codex 运行：11 项，通过。未创建额度读取器、任务监视器和 Token 读取器；活动范围不依赖 Codex 窗口。
- 原宠物渲染：24 项，通过，180 帧只分配一次画布，画面校验值与基线相同。
- 实机只读：新版视觉消息栏读取两次，分别为 736 毫秒、764 毫秒；无真实消息发送。此前整棵控件读取约 5.8 秒、5.6 秒，仅作为旧路径对照。
- 实机完整单人检查模式通过，用时 25.9 秒（诊断为 25,884 毫秒）：`InspectOnly=true`、`Outcome=complete`、最终阶段 `emoji-ready`，联系人状态为“检查通过”，当天尝试及发送日期均为空。该轮找到了联系人对话和续火花表情，未点击发送。
- 旧的 .NET 控件遍历在本机抖音上超时；预览版 4 优先使用 Windows 局部 OCR 与原生控件点查，缺少 OCR 时使用原生 COM 控件兼容路径。读取由短时子进程隔离，不保留常驻读取进程。
- 预览版 4 开始任务后隐藏管理器，托盘可停止；宠物引导移动约 0.18～0.55 秒，页面等待阶段具有 8 秒轮询预算，完成时显示耗时。
- 视觉路径不推断图片发送回执，缺少明确回执时显示“已点击·待确认”，当天不自动重复发送。
- 最近一轮读取摘要保存在体验数据目录的 `douyin-last-run.json`，包含阶段、查询是否一致、完全匹配数、结果总数、界面就绪状态、识别后端及耗时；不记录查询文本、联系人名称或聊天正文。
- 尚未对真实联系人执行发送验证，也未验证整份名单一分钟内完成真实发送。单人检查模式的 25.9 秒不能等同于整份名单或真实发送的耗时。`main` 稳定版及其更新渠道未改动。

本机确认 `ValuePattern.SetValue` 可能仅回显名称而不触发抖音实际过滤，预览版 4 因此统一使用已验证焦点的 Unicode 键盘输入，并保留 Legacy/Text 回读核对。聊天标题通过原生定向读取取得完整名称；发送箭头的嵌套图像先去重再选表情按钮，修复此前误点发送箭头的问题。截图、隔离流程、只读耗时及检查模式结果均不作为真实消息已发送的证据。
